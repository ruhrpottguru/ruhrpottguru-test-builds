CODE DEFECT CLOSED
- In 1.10.39 the main frontend_events_query() first selected media by occurrence/database event_id.
- That generic selection admitted both localized exact ET4 media and older healthy ET4/feed media, and its ordering did not make local_cache_status=ready + source=et4-global-id an absolute first choice.
- The local cache itself is keyed by ET4 global_id, not by occurrence event_id.
- A late rest_request_after_callbacks filter attempted to re-hydrate the response by global_id, but the main visitor payload did not itself enforce the same invariant.

1.10.40 INVARIANT
1. Event rows are filtered, source-owned and series-clustered first.
2. Only then are the visible ET4 external_id/global_id values collected.
3. Those ids are resolved directly against the current master event_media rows where:
   source=et4-global-id, moderation_status=active,
   local_cache_status=ready, local_path is non-empty.
4. That exact local media row wins before any event_id media candidate.
5. The local static uploads URL is written directly into media_objects, rpg_event_media, image and imageUrl in frontend_events_query().
6. Theme v232 can therefore consume the local URL without depending on the late REST filter.
7. The late REST filter remains only as a defensive second invariant.
8. The existing 316 cached files are reused. 1.10.40 does not reset or redownload the completed local cache.

QUERY HARDENING
- The event_id batch media query now also explicitly orders a ready local et4-global-id row before all other image rows.
- This prevents older et4-event-feed/enrichment rows without local_path from winning the generic occurrence-media selection.
