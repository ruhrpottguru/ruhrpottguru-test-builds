RUHRPOTTGURU PLACES BACKEND 1.10.24
ET4 CANONICAL EVENT MEDIA - FINAL VERIFICATION
Date: 2026-09-04

ROOT CAUSE
- RuhrpottGuru persists concrete event occurrences for the 365-day event list.
- ET4 also has a unique/canonical event-object representation containing the event-owned media_objects.
- The previous repair assumed that occurrence and canonical rows could always be connected by the same external/global/hash ID.
- That assumption is not safe across ET4/destination.one representations. A rich catalog item could therefore have an image while the persisted occurrence remained image-less.
- The frontend was behaving correctly: if no normalized event image reached the visitor JSON, it rendered the ticket fallback.

FINAL DATA FLOW
1. ET4 unique catalog object is the authoritative source for event-owned artwork.
2. media_objects is parsed strictly; page/canonical/homepage/booking/video/audio links are rejected as images.
3. Catalog object -> stored occurrence is joined by:
   a) a genuinely shared source ID, otherwise
   b) exact normalized ET4 event title + same city + matching geo (<=2 km), or
   c) exact title + same city + compatible venue, or
   d) exact sufficiently-specific title + same city + same postcode when geo/venue are unavailable.
4. Wrong-city and geographically conflicting candidates are rejected.
5. One canonical catalog image is persisted to every matching active occurrence, so category lists, search and detail use the same image.
6. Visitor requests no longer perform speculative hashlink/global-id lookup loops.
7. The nightly master changes to unique=true source objects and performs recurrence expansion locally. This preserves the rich ET2014A source object (including event media) for future imports.
8. A fresh v1.10.24 catalog-media reconciliation starts automatically after update and after each completed nightly master run.

SOURCE / SCHEMA AUDIT
- ET4 search documentation: unique=true removes duplicate object renderings; unrollIntervals is specifically for rendered chronological occurrence lists.
- ET2014A examples expose event-owned images in media_objects with rel/url/type metadata.
- RuhrpottGuru master already has its own local recurrence expansion; therefore using rich unique source objects is the consistent source model.
