RUHRPOTTGURU PLACES BACKEND 1.10.126
REPROCESSING STANDARD — FINAL ACCEPTANCE / HARDENING

PURPOSE
- Final acceptance of the central 1.10.95 reprocessing standard.
- Close two verified contract gaps without replacing the existing architecture.

VERIFIED GAPS IN 1.10.125
1) The documented cursor guarantee said progress was persisted after every entity,
   but the worker only persisted once after the batch.
2) A new managed job without an explicit autostart flag defaulted to pending,
   although the standard promises that a new/changed fingerprint is queued once.

1.10.126 HARDENING
- Managed non-historical jobs now default to autostart=true.
- Dependency-gated jobs can still explicitly set autostart=false.
- Existing keys/fingerprints/states/cursors are preserved when the fingerprint is unchanged.
- Changed fingerprints reset exactly one managed job pass to queued + cursor 0.
- Cursor/state/statistics are persisted immediately after every processed entity.
- Reprocessing API contract version raised from 1.0 to 1.1 and persisted.
- No schema migration; SCHEMA_VERSION remains 1.10.22.
- No Event, Place, REST, ranking, radius, media-policy, lifecycle or frontend logic changed.

ACCEPTANCE
The central reprocessing standard is now suitable as the required default path for
future resolver/parser/classifier changes that must update existing persisted data
without a source reimport. A processor itself still has to be deterministic/idempotent,
while the framework guarantees one pass per fingerprint, resumable per-entity progress,
worker conflict gating and persistent audit state.
