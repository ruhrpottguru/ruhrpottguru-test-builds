RuhrpottGuru Places Backend v1.10.98 – Broad Radius Event REST FINAL

Root cause verified:
- Halloween v280 expands 5 km -> 10 km -> 25 km only after the prior request completed without an error.
- The failing screenshot was already at 25 km, so 5 km and 10 km had completed successfully.
- In v1.10.97, rest_request_after_callbacks executed event_manual_place_pool_candidate_v1076() once for every image-less event in the /events response.
- That helper performs event/place/media DB lookups per item. A 600-item synthetic response executed 600 event-row lookups + 600 place lookups (and 618 get_results calls overall), i.e. an unbounded N+1 path whose cost grows with radius.
- The six rpg_seasonal_editorial Halloween rows themselves serialize correctly through frontend_events_query() and the REST media filter in isolation; the error is not a missing seasonal field.

- Bulk /wp-json/ruhrpottguru/v1/events keeps only batched media paths: exact localized ET4/destination.one media and already stored event-specific fallback media.
- Per-item manual Place-pool lookup is removed from the bulk list response.
- Direct/share event detail retains the existing bounded one-event manual Place-pool fallback via event_finalize_direct_media_v1078().
- rpg_seasonal_editorial IDs are no longer sent through the ET4 exact-media identity query.
- No event is hidden because it has no image.
