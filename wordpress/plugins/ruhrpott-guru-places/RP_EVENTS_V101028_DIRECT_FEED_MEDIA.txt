RuhrpottGuru Places Backend 1.10.28 – ET4 direct feed media persistence

Verified root cause
- v1.10.27 correctly upgraded master + destination.one supplemental fetches to rich unique ET2014A objects.
- event_upsert_from_feed_item() persisted the rich object only into rg_events.raw_payload.
- Visitor rendering reads persistent rg_event_media, not raw_payload directly.
- Existing rows already terminally marked checked_no_media were excluded from later enrichment batches (which process only pending/retry/partial).
- Therefore a rich payload could contain the correct ET4 image while the visitor card stayed on the red ticket fallback indefinitely.

Fix
1. For trusted ET4 sources open_data_finder / destination_one_open_data / et4, event_upsert_from_feed_item() now extracts the event-owned image immediately and persists it via event_store_authoritative_feed_media_v1022().
2. ET4 feed artwork stays authoritative and becomes the primary media row immediately; no remote image-health roundtrip blocks visitor rendering.
3. checked_no_media / checked_incomplete is promoted to complete when authoritative ET4 media is stored.
4. One-time local raw-payload backfill scans all active ET4/destination.one rows and persists already-present images without external research.
5. If the v1.10.27 rich supplemental worker is still running, the backfill performs a final second pass only after that worker finishes. This closes the race for cities updated while the first local pass was in progress.
6. Current supplemental state is not restarted or reset. Opening-hours audit state/options/hooks are unchanged.
